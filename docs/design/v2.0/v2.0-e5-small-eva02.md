# mini-embed-vision v2.0 — 全栈双语版

> 设计时间：2026-08-21
> 文本编码器：`intfloat/multilingual-e5-small`（冻结，118M，hidden=384，100+ 语言）
> 视觉编码器：`timm/eva02_base_patch14_224.mim_in22k`（可训练，~90M）
> 输出维度：768

---

## 1. 概述

v2.0 是架构全面升级：**文本编码器换成双语 e5-small，视觉编码器换成 EVA02**。目标是解锁英文/跨模态 benchmark 能力，同时通过更强的视觉骨干提升所有任务的性能。

## 2. 架构变更

```
v1.0（当前）:
  文本输入 → bge-base-zh (冻结, 768d) → Identity → 768d L2-norm
  图片输入 → CLIP-ViT-B/32 (可训练)   → [CLS] 768d → Identity → 768d L2-norm

v2.0（全栈双语）:
  文本输入 → e5-small (冻结, 384d) → Linear(384→768) → 768d L2-norm  ← 双语
  图片输入 → EVA02-Base (可训练)    → ProjectionHead  → 768d L2-norm  ← 更强
```

### 2.1 文本侧变更

| 维度 | bge-base-zh (v1.0) | e5-small (v2.0) | 影响 |
|------|-------------------|-----------------|------|
| 参数量 | 102M | 118M | **+15%，可忽略** |
| 隐藏维度 | 768 | **384** | 须加投影层 |
| tokenizer 词表 | ~21k (中文) | ~250k (多语) | 充实的多语词表 |
| 支持语言 | 仅中文 | **100+ 语言** | 本质变化 |
| 池化策略 | CLS | CLS（e5 已有 `<s>`） | 可用 cls |
| 投影层 | Identity（0 参数） | Linear(384→768) | +295K 参数 |

e5-small 的关键优势：**虽然是 small 版本（hidden=384），但多语词表使得它对英文/中文的 token 覆盖远超 bge-zh**。384→768 的投影层增加约 1.2 MB 参数。

### 2.2 视觉侧变更

| 维度 | CLIP-ViT-B/32 (v1.0) | EVA02-Base (v2.0) | 影响 |
|------|----------------------|--------------------|------|
| 架构 | ViT-B/32 | ViT-B/14 | 更细粒度 |
| patch 数 | 49 (224/32) | 196 (224/14) | 4× 更多 patch |
| 预训练 | CLIP 400M | ImageNet-22k + MIM | 更强的视觉 |
| 隐藏维度 | 768 | 768 | 不变 |
| 参数量 | 87M | ~90M | 基本持平 |
| 投影层 | Identity | ProjectionHead | +590K 参数 |
| 推理速度 | 1× | ~1.3× | 稍慢 |

## 3. 完整参数对比

| 组件 | v1.0 (bge-zh + CLIP) | v1.5 (bge-zh + EVA02) | **v2.0 (e5 + EVA02)** |
|------|:--------------------:|:---------------------:|:--------------------:|
| text_encoder（冻结） | 102M | 102M | **118M** |
| vision_encoder（可训练） | 87M | ~90M | **~90M** |
| text_proj（可训练） | 0 | 0 | **295K** |
| vision_proj（可训练） | 0 (Identity) | ~590K (ProjectionHead) | **~590K** |
| **可训练总计** | **87M** | **~90.6M** | **~90.9M** |
| **全量导出** | ~756 MB | ~771 MB (含 text_proj) | **~829 MB** (−e5 118M vs bge-zh 102M) |

核心结论：v2.0 可训练参数只比 v1.0 多 **~3.3M (4%)**，全量导出模型比 v1.0 多 **~73 MB (10%)**。这才是你当时担心的模型权重变大问题——对 e5-small + EVA02 而言，增量非常小。

## 4. 数据

### 4.1 数据集组成

| 数据集 | 语言 | 数量 | 来源 | 状态 |
|--------|------|------|------|------|
| ImageNet-zh | 中文 | 183k | 已有，VLM 生成 | ✅ 已就绪 |

### 4.2 英文数据生成

复用 `generate_image_caption.py`，仅修改 prompt：

```python
CAPTION_PROMPT_EN = (
    "Describe the main subject, key details, and scene visible "
    "in this image in one concise objective sentence."
)
```

在现有脚本上加 `--prompt-lang en` 参数（后续实现）：

```bash
python generate_image_caption.py --limit 0 --concurrency 32 \
    --output data/imagenet-1k-captions/train_captions_en.jsonl
```

预估耗时：~0.5-0.7s/张，18 万条约 **1-2 天**（受限于 VLM 后端并发能力）。

### 4.3 数据混合策略

**推荐：统一 shuffle（改动最小）**

```python
from datasets import load_dataset, concatenate_datasets

zh = load_dataset("parquet", data_dir="data/imagenet-1k-zh-captions", split="train")
en = load_dataset("parquet", data_dir="data/imagenet-1k-en-captions", split="train")
merged = concatenate_datasets([zh, en]).shuffle(seed=42)
merged.save_to_disk("data/imagenet-1k-bilingual-captions")
```

### 4.4 跨语言隐式对齐

通过共享的 image encoder，中英文文本在 embedding 空间实现隐式对齐：

```
图片"金毛犬接飞盘"
    ↕ EVA02 → image_emb
    ↑        ↓
zh_text → e5 → text_emb_zh
en_text → e5 → text_emb_en

对比学习迫使 image_emb 同时接近 text_emb_zh 和 text_emb_en，
→ text_emb_zh ≈ text_emb_en（未经过翻译，自然对齐）
```

## 5. 训练

### 5.1 命令行

```bash
# 仅中文数据（快速验证）
python train.py \
    --text-model intfloat/multilingual-e5-small \
    --vision-backend timm \
    --timm-model-name eva02_base_patch14_224 \
    --data-dir data/imagenet-1k-zh-captions \
    --max-text-len 512

# 中英双语（正式训练）
python train.py \
    --text-model intfloat/multilingual-e5-small \
    --vision-backend timm \
    --timm-model-name eva02_base_patch14_224 \
    --data-dir data/imagenet-1k-bilingual-captions \
    --max-text-len 512

# DDP
torchrun --nproc_per_node=3 train.py \
    --text-model intfloat/multilingual-e5-small \
    --vision-backend timm \
    --timm-model-name eva02_base_patch14_224 \
    --batch-size 128 --epochs 30 --lr 2e-5 --max-text-len 512
```

### 5.2 超参建议

| 参数 | v1.0 | v2.0 建议 | 原因 |
|------|------|-----------|------|
| lr | 2e-5 | **1e-5 ~ 2e-5** | EVA02 + 新投影层，低 lr 更稳 |
| warmup-ratio | 0.05 | **0.1** | EVA02 + 新投影层需更多 warmup |
| batch-size | 128 | **128**（可调） | 不变 |
| max-text-len | 128 | **512** | 英文同义句 ≈ 中文 1.5-2× token 数 |
| epochs | 30 | **30-50** | 双语数据量加倍，训练更长 |
| image_size | 224 | **224**（可调 448） | 不变 |

### 5.3 需要验证的点

| 项目 | 原因 | 验证方法 |
|------|------|----------|
| e5-small tokenizer pad_token | 部分 tokenizer pad_token=None，需用 eos_token 回退 | 加载后打印 tokenizer.pad_token_id |
| pooling 策略 | e5-small 输出 `<s>`（[CLS]）在 last_hidden[:,0] | 对比 cls vs mean pooling |
| text_proj 初始化 | Linear(384→768) 随机初始化，影响早期 loss | 跟踪第 1 个 epoch loss 下降速度 |
| EVA02 权重加载 | 需确认本地 cache 路径 | `_load_timm_vision_model` 加载 safetensors |
| 英文 caption 质量 | VLM 英文能否生成一致描述 | 抽检 100 条，与中文描述的语义一致性 |

## 6. Benchmark

### 6.1 覆盖范围

| 任务 | v1.0 (bge-zh+CLIP) | v1.5 (bge-zh+EVA02) | **v2.0 (e5+EVA02)** |
|------|:------------------:|:-------------------:|:------------------:|
| ImageNet-1k 分类 | ✅ | ✅ 更高 | **✅ 更高** |
| C-MTEB（全部中文） | ✅ | ✅ | **✅（可能小降）** |
| **Flickr30k T2I** | ❌ | ❌ | **✅ 新增** |
| **Flickr30k I2T** | ❌ | ❌ | **✅ 新增** |
| MTEB 英文分类 | ❌ | ❌ | **✅ 新增** |
| MTEB 英文 STS | ❌ | ❌ | **✅ 新增** |
| MTEB 英文聚类 | ❌ | ❌ | **✅ 新增** |

### 6.2 预期性能

预估，参考 e5-small 在 MTEB 上的基线：

| 任务类型 | MTEB e5-small 基线 | v2.0 预估 | 说明 |
|----------|:-----------------:|:----------:|------|
| English Classification | ~72% | ~70-72% | 略低，因有中文干扰 |
| English STS | ~76% | ~74-76% | 同上 |
| **Flickr30k R@1 (T2I)** | N/A | **~35-45%** | 视觉+英文首次对齐，CLIP 基线 ~65% |
| C-MTEB 中文 | N/A | ~55-60% | 可能略低于 bge-zh (~62%) 的纯中文场景 |
| ImageNet 分类 | N/A | ~80-84% | EVA02 视觉增益 |

**重要：Flickr30k 的 R@1 基准**
- CLIP-ViT-B/32 本身在 Flickr30k R@1 约 65%
- v2.0 首次训英文跨模态，预估 35-45%，因为：
  - e5-small 的英文编码能力（384d）弱于原始 CLIP text encoder（512d）
  - 数据量少（18 万 vs CLIP 4 亿）
- 但这个数字至少是**有意义的、可比对的**，比 v1.0 的❌强

## 7. 模型体积

| 组件 | v1.0 (fp32) | v1.5 (fp32) | v2.0 (fp32) | 变化(v2.0 vs v1.0) |
|------|:-----------:|:-----------:|:-----------:|:------------------:|
| text_encoder（冻结） | ~408 MB | ~408 MB | **~470 MB** | +62 MB |
| vision_encoder（可训练） | ~348 MB | ~360 MB | **~360 MB** | +12 MB |
| text_proj | 0 | 0 | **~1.2 MB** | +1.2 MB |
| vision_proj | 0 | ~2.4 MB | **~2.4 MB** | +2.4 MB |
| logit_scale | 忽略 | 忽略 | 忽略 | 0 |
| **全量导出** | ~756 MB | ~770 MB | **~829 MB** | **+73 MB (+10%)** |
| **checkpoint（仅可训练权重）** | ~348 MB | ~362 MB | **~363 MB** | **+15 MB (+4%)** |

实测——**你之前担心的模型权重变大问题，对 e5-small + EVA02 来说增量很小**：可训练参数只多 4%，全量导出多 10%。只有换 bge-m3 那种 567M 级别的模型才会是 5× 膨胀。

## 8. 与 v1.0、v1.5 的关系

```
v1.0 (bge-zh + CLIP-ViT-B/32)  →  纯中文基线
               ↓
        v1.5 (bge-zh + EVA02)  →  纯中文，视觉更强，R@1 ~65-70%
               ↓
   v2.0 (e5-small + EVA02)     →  中英双语，benchmark 全对齐，视觉更强
```

v1.5 和 v2.0 是**独立分支**，不是增量关系：
- 核心区别在于文本编码器（中文 vs 双语）
- 权重不能互相迁移
- 训练数据量不同（v1.5 单中文 vs v2.0 中英混合）

## 10. 回归风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 中文性能下降（e5 < bge-zh） | 中 | C-MTEB 降 1-5pp | 保留 v1.0/bge-zh 分支；若不可接受可保持 bge-zh + EVA02（v1.5） |
| 英文 caption 质量差 | 低 | 中英不对齐 | 抽检 100 条；VLM 英文通常优于中文 |
| e5-small 384d 损失过多信息 | 低 | 双语都差 | 对比 e5-small vs e5-base 的基线 benchmark |
| EVA02 训练不稳定 | 低 | loss 不降 | 降低 lr、增加 warmup |
| 推理变慢 | 高 | ~1.3× visual + 无关 text | 可接受 |

## 11. 版本选择指南

| 场景 | 推荐版本 |
|------|----------|
| 仅需中文能力，追求极致 | **v1.0** (bge-zh + CLIP) 或 **v1.5** (bge-zh + EVA02) |
| 需要英文跨模态 benchmark | **v2.0** |
| 需要中文 + 英文都最好 | **v2.0** + 更大数据量（下一阶段） |
| 模型体积敏感（移动端） | **v1.0**（最小 756 MB） |
| 追求最高视觉精度 | **v1.5** 或 **v2.0**（EVA02） |
