# mini-embed-vision v1.5 — 视觉升级 + 任务感知版

> 设计时间：2026-08-21
> 文本编码器：`BAAI/bge-base-zh-v1.5`（冻结，102M，hidden=768）— 不变
> 视觉编码器：`timm/eva02_base_patch14_224.mim_in22k`（可训练，~90M）— 升级
> 输出维度：768
> 核心新增：任务感知 Prompt 前缀 + 多任务训练 + 检索器时序衰减

---

## 1. 概述

v1.5 包含两方面的升级：

**A. 视觉编码器升级**：CLIP-ViT-B/32 → EVA02-Base（patch14），原生 SwiGLU + RoPE + Flash Attention，更强的视觉表征突破 R@1 瓶颈。

**B. 任务感知训练**：从"图文对比学习"全面升级为"多任务 embedding 训练"，引入 prompt 前缀体系，让模型通过前缀区分任务上下文。

同时将**时序衰减**设计在检索器层，不侵入 embedding 模型本身。

---

## 2. 任务定义

### 2.1 任务矩阵

| 优先级 | 任务 | 角色 | 描述 |
|:------:|------|------|------|
| **P0** | 以文搜图（T2I） | **核心** | text query → 检索图像 |
| **P1** | 文本检索（T2T） | **Agent 记忆检索器** | text query → 检索文本 passage |
| **P2** | 混合检索 | **扩展** | text query → 一次检索同时召回图像+文本 |

### 2.2 P0：以文搜图（Text-to-Image）

**当前已有**：18 万条 ImageNet 中文 caption，直接用。

**唯一变化**：训练时文本侧加 `"search_query: "` 前缀，让 embedding 空间区分 query 和 document。

```
训练：encode_text("search_query: 一只金毛犬在草地上接飞盘") ↔ encode_image(...)
推理：encode_text("search_query: 金毛犬接飞盘") → 余弦相似度 → 检索图片
```

### 2.3 P1：文本检索（Text-to-Text）

Agent 记忆检索器的核心能力。需要构造 text↔text 正负例：

```
训练：
  query端: encode_text("search_query: 昨天会议讨论了什么议题？")
  corpus端: encode_text("search_document: 会议主要讨论了 v1.5 架构升级计划")

推理：
  encode_text("search_query: 会议关于架构做了什么决定")
     ↓ 余弦相似度
  排序全体 corpus（全部已预编码为 "search_document: {doc}"）
```

### 2.4 P2：混合检索（Text → Image + Text）

前两个任务的自然统一。训练时 query 前缀 `"search_query: "` 同时对齐图像和文本 corpus：

```
同一个 query 向量:
  query: "search_query: 金毛犬接飞盘"
     ↙                                  ↘
  image_emb[金毛犬接飞盘.jpg]          text_emb["search_document: 金毛犬是一种寻回猎犬"]
     ↕ 余弦 ≈ 0.85                        ↕ 余弦 ≈ 0.78
  排序第 1                              排序第 3
```

**训练时不区分正例类型**——`"search_query: "` 同时和 image 配对（P0 数据）也与 `"search_document: "` 配对（P1 数据），模型自动对齐。

## 3. Prompt 前缀体系

采用英文前缀，与 Nomic Embed、BGE、E5 等主流方案对齐。前缀只在 text 侧使用，image 端不需要前缀。

### 3.1 前缀表

| 前缀 | 含义 | 使用场景 |
|------|------|----------|
| `"search_query: {query}"` | 检索的**目标** | T2I query、T2T query、混合 query |
| `"search_document: {passage}"` | 检索库中的**文本** | T2T corpus、分类标签、描述 |
| `"classification: {label}"` | 分类任务的标签 | 图像分类标签映射 |
| 无 | 原始语义 | 无前缀时退化为 raw embedding，用于 STS 等 |

### 3.2 设计思路

- `"search_query:"` 只出现在 query 端，统一了 T2I 和 T2T 的查询入口
- `"search_document:"` 只出现在 corpus 端 text，区分"被检索的文档"和"查询语句"
- 训练时 `"search_query:"` 的向量同时靠近 image 和 `"search_document: {text}"`，自然实现混合检索
- 英文前缀与 bge-zh tokenizer 兼容（BERT 词表包含英文子词），token 数也极少

### 3.3 参考：Nomic Embed 的 prefix 体系

Nomic-embed-vision-v1.5 的处理方式（[官方 README](https://huggingface.co/nomic-ai/nomic-embed-vision-v1.5)）：

> "when using Nomic Embed in multimodal RAG scenarios, you should use the `search_query:` prefix."

```python
# Nomic 的用法
sentences = [
    'search_query: What are cute animals to cuddle with?',
    'search_query: What do cats look like?'
]

# image 端不需要 prefix
img_embeddings = F.normalize(img_emb[:, 0], p=2, dim=1)
text_embeddings = mean_pooling(model_output, encoded_input['attention_mask'])
text_embeddings = F.layer_norm(text_embeddings, normalized_shape=(text_embeddings.shape[1],))
text_embeddings = F.normalize(text_embeddings, p=2, dim=1)

# 此时 img_embeddings 和 text_embeddings 在同一空间，可直接点积
print(torch.matmul(img_embeddings, text_embeddings.T))
```

Nomic 保持 image encoding 纯净（无 prefix），所有任务区分通过 text 前缀完成。v1.5 采用完全一致的策略。

### 3.4 对比主流方案

| 方案 | query 前缀 | corpus 前缀 | 训练方式 |
|------|-----------|------------|----------|
| **v1.5 本方案** | search_query: | search_document: | 多任务混合训练 |
| **Nomic** （对标） | search_query: | search_document: | 冻结 text encoder，LiT 风格 |
| BGE | query: (en) | passage: (en) | 两段式预训练 |
| E5 | query: (en) | passage: (en) | 两段式预训练 |

### 3.5 encode 时自动加前缀

`model.py` 新增 `prompt_type` 参数：

```python
PROMPT_PREFIX = {
    "query": "search_query: ",
    "document": "search_document: ",
    "classification": "classification: ",
}

def encode_text(
    self,
    input_ids,
    attention_mask,
    prompt_type: str | None = None,  # "query" | "document" | "classification" | None
    raw_texts: list[str] | None = None,  # 提供 raw text 则由 tokenizer 本地拼接前缀
):
    if prompt_type and raw_texts:
        # 在 tokenizer 层加前缀，保证和训练时一致
        prefixed = [PROMPT_PREFIX[prompt_type] + t for t in raw_texts]
        encoded = tokenizer(prefixed, ...)
        input_ids, attention_mask = encoded...
    # ... 剩余 encode 逻辑不变
```

## 4. 架构

### 4.1 总览

```
v1.5:

  文本输入（自动加 prompt 前缀）
       ↓
  bge-base-zh-v1.5（冻结，102M）
       ↓
  [CLS] 768d
       ↓
  Identity（hidden=768 == embed_dim=768）
       ↓
  [search_query: xxx] → 768d L2-norm          ← query 用
  [search_document: xxx] → 768d L2-norm          ← corpus text 用

  图片输入
       ↓
  EVA02-Base（可训练，~90M）
    ├── PatchEmbed (14×14, 196 patches)
    ├── RotaryEmbeddingCat (RoPE)        ← 原生
    ├── EvaBlock × 12
    │   ├── EvaAttention (Flash Attention) ← 自动
    │   └── SwiGLU MLP                    ← 原生
    └── fc_norm (LayerNorm 768)
       ↓
  ProjectionHead（可训练，~590K）
    ├── Linear 768→768
    ├── GELU
    ├── Dropout
    └── LayerNorm 768
       ↓
  image → 768d L2-norm
```

### 4.2 文本侧变化

| | v1.0 | v1.5 |
|--|------|------|
| 文本编码器 | bge-base-zh（冻结） | 不变 |
| 文本投影层 | Identity | 不变 |
| 编码方式 | raw text → embedding | `search_query:/search_document:/classification:` + raw text → embedding |
| encode_text 接口 | input_ids, attention_mask | 新增 `prompt_type` + `raw_texts` 参数 |

### 4.3 视觉侧变化

| 维度 | CLIP-ViT-B/32 (v1.0) | EVA02-Base (v1.5) | 说明 |
|------|----------------------|--------------------|------|
| 架构 | ViT-B/32 | ViT-B/14 | patch 更小，粒度更细 |
| 输入尺寸 | 224×224 | 224×224 | 兼容旧处理器 |
| patch 数 | 49 | **196**（4×） | 更多细粒度信息 |
| 位置编码 | 可学习绝对位置 | **RoPE** | 原生，更优外推 |
| MLP | Linear+GELU | **SwiGLU**（fc1_g + fc1_x + SiLU） | 原生，~+1-2pp |
| 注意力 | 手动 attn @ v | **Flash Attention**（F.scaled_dot_product_attention） | 原生自动启用 |
| 池化 | [CLS] token | fc_norm（LayerNorm） | timm 默认，需投影层 |
| 投影层 | Identity（0 参数） | ProjectionHead（~590K 参数） | GELU+Dropout+LayerNorm |
| 参数量 | 86.57M | ~90M | +3.4M |
| 预训练 | CLIP 400M 图文 | ImageNet-22k + MIM | 更强视觉 |

### 4.4 为什么 EVA02 需要 ProjectionHead

```python
# EVA02 的池化方式（timm 默认）
output = model.forward_features(x)  # [B, 197, 768]
# fc_norm 用的是所有 tokens 的均值池化（不是 [CLS]）
# 输出 [B, 768] 但 distribution 和 CLIP [CLS] 不同

# 所以需要 projection 调整到 CLIP 风格的 embedding 空间
self.vision_proj = ProjectionHead(768, 768, dropout=0.0)
# ← GELU → Linear(768→768) → LayerNorm(768)
```

对比 v1.0 的 CLIP 路径：

```python
# v1.0: CLIP 自带 [CLS] 且 hidden=768 == embed_dim=768 → Identity
# v1.5: EVA02 fc_norm 输出分布和 CLIP 不同 → ProjectionHead 映射
```

### 5.3 需要构建：T2T 检索

Agent 记忆检索器需要 text↔text 正例。几个构建途径：

**途径 A：自构造（推荐立即做）**

用现有的 ImageNet caption 构造"查询 → 自身描述"对：

```python
# query 端
"search_query: 金毛犬接飞盘"
# passage 端（同一行数据，不同前缀）
"search_document: 一只金毛犬在草地上接飞盘"
```

**T2T 的正例就是 T2I 的同一条数据改个前缀**。这样 T2I 和 T2T 共享同一个语义空间，天然对齐。

**途径 B：C-MTEB 训练集（后续加入）**

- T2Retrieval 训练集（中文 query↔document 对）
- MMarcoRetrieval 训练集（中文搜索 query↔passage 对）
- 这些自带真实 query/文档对，比自构造更真实

**途径 C：Agent 场景（规划中的后续）**

- 对话历史 → (query, response) 对
- 工具调用 → (instruction, tool_desc) 对
- 需要和 agent 应用场景结合收集

## 6. 训练

### 6.1 训练目标

```
Loss = InfoNCE(对比学习)

每个 batch 包含：
- T2I 数据：query 向量 ↔ 图像向量 为正例，其他 batch 内为负例
- T2T 数据：query 向量 ↔ search 向量 为正例，其他 batch 内为负例

所有数据共享同一个对比学习 loss，不区分任务来源。
```

### 6.2 命令行

```bash
# 基础训练（仅 T2I + 自构造 T2T）
python train.py \
    --vision-backend timm \
    --timm-model-name eva02_base_patch14_224 \
    --data-dir data/imagenet-1k-zh-captions \
    --use-prompt                         # 启用 prompt 前缀

# 多卡
torchrun --nproc_per_node=3 train.py \
    --vision-backend timm \
    --timm-model-name eva02_base_patch14_224 \
    --batch-size 128 --epochs 30 --lr 1e-5 \
    --use-prompt --max-text-len 512
```

### 6.3 训练策略

| 超参 | v1.0 (CLIP-ViT) | v1.5 (EVA02) | 原因 |
|------|:----------------:|:------------:|------|
| lr | 2e-5 | **1e-5** | EVA02 + 新投影层，低 lr 更稳 |
| warmup | 0.05 | **0.1** | EVA02 预训练非 CLIP style，需更多 warmup |
| batch size | 128 | 128 | 不变 |
| grad accum | 1 | **2** | 更多负例有助于收敛 |
| epochs | 30 | **30-50** | 混合训练需更多迭代 |
| max text len | 128 | **512** | task prompt 占额外 token，且 T2T doc 更长 |
| image size | 224 | 224 | 与 EVA02 预训练一致 |
| vision_backend | transformers | timm | 新后端 |

## 7. 检索器设计

这是 v1.5 新引入的组件，不在 embedding 模型内部，而是 agent 调用时的检索层。

### 7.1 检索器架构

```
┌──────────────────────────────────────────────────┐
│  Agent                                            │
│  ┌──────────────────────────────────────────────┐ │
│  │  记忆检索器（HybridRetriever）                │ │
│  │                                              │ │
│  │  encode(query) → query_emb ← v1.5 model     │ │
│  │       ↓                                      │ │
│  │  ┌──── Index ────┐                          │ │
│  │  │  image_emb₁   │ ← 预编码图片               │ │
│  │  │  text_emb₂    │ ← 预编码文档               │ │
│  │  │  image_emb₃   │                          │ │
│  │  │  ...          │                          │ │
│  │  └──────┬───────┘                          │ │
│  │         ↓                                   │ │
│  │  ┌─── Scorer ────┐                         │ │
│  │  │  s = α × sim  +  (1-α) × time_decay    │ │
│  │  │      语义分          时序分               │ │
│  │  └──────┬───────┘                          │ │
│  │         ↓                                   │ │
│  │   排序结果                                 │ │
│  └──────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

### 7.2 时序衰减设计（检索器层）

时序衰减不在 embedding 模型内部实现，而是检索器的 scorer 层。这样 embedding 模型保持纯粹语义对齐，使用者可以动态配置衰减策略。

**衰减公式**：

```python
def hybrid_score(query_emb, doc_emb, doc_timestamp, config):
    """
    query_emb: encode_text("search_query: {query}")
    doc_emb: encode_image() 或 encode_text("search_document: {doc}")
    doc_timestamp: 文档的写入时间
    """
    semantic = cosine_similarity(query_emb, doc_emb)
    
    # 时序衰减
    hours_old = (now - doc_timestamp).total_seconds() / 3600
    if config.decay_strategy == "exponential":
        temporal = config.gamma ** hours_old      # γ^小时数
    elif config.decay_strategy == "linear":
        temporal = max(0, 1 - hours_old / config.max_hours)
    elif config.decay_strategy == "none":
        temporal = 1.0
    
    return config.alpha * semantic + (1 - config.alpha) * temporal
```

**可配置参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `alpha` | 0.8 | 语义分权重 0.0(只看时效)→1.0(只看语义) |
| `decay_strategy` | "exponential" | exponential / linear / none |
| `gamma` | 0.99/h | 指数衰减率，0.99^24h≈0.78(一天后) |
| `max_hours` | 720 (30天) | 线性衰减的完全衰减时间 |

**使用示例**：

```python
retriever = HybridRetriever(model, index, alpha=0.8, gamma=0.99)

# 默认检索（α=0.8，轻时序衰减）
results = retriever.search("search_query: 昨天会议讨论了什么？")

# 纯语义检索（不看时间，等于普通 embedding 检索）
results = retriever.search("search_query: EVA02 的参数量是多少？", alpha=1.0)

# 只看最近（时序主导）
results = retriever.search("search_query: 今天谁发过消息？", alpha=0.3)
```

### 7.3 为什么不在 embedding 层做

| 方案 | 优点 | 缺点 |
|------|------|------|
| **检索器层做（本方案）** | 可配置、不改模型、灵活 | 需额外传递时间元数据 |
| embedding 层做（方案 2） | 完全端到端 | 衰减策略固化、需重训才能改 |
| 训练时加入时间编码 | 模型感知时间 | 静态时间窗口、泛化差 |

代理场景需要的是灵活——"找昨天说过的"和"全部相关的"应该是同一个索引的两种视角。

### 7.4 检索器数据流

```
写入时:
  doc = {"text": "昨天会议决定升级到 EVA02", "timestamp": "2026-08-20T10:00:00"}
  emb = model.encode_text("search_document: 昨天会议决定升级到 EVA02")
  index.add(emb, metadata={"timestamp": doc.timestamp, "text": doc.text, "type": "text"})

  image = Image.open("meeting_notes.png")
  emb = model.encode_image(image)
  index.add(emb, metadata={"timestamp": "2026-08-20T10:00:30", "text": "会议笔记截图", "type": "image"})

检索时:
  query_emb = model.encode_text("search_query: 架构升级决定")
  results = retriever.search(query_emb, alpha=0.8, gamma=0.99/h)
  # 返回排序后的混合结果（图像+文本混合在一个列表中）
```

## 11. 回归风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|:----:|------|------|
| EVA02 下收敛不如 CLIP-ViT | 中 | R@1 不升反降 | 更长的 warmup、更低 lr |
| prompt 前缀反而降低无前缀场景性能 | 中 | STS 等任务掉点 | 评估时支持无前缀 fallback |
| ProjectionHead 成为瓶颈 | 低 | 容量限制 | 使用 GELU+LayerNorm 结构已足够 |
| 混合训练中 T2T 干扰 T2I | 低 | 双方都差 | 调整混合比例、分阶段训练 |
| 推理速度变慢 | 高 | 1.3× | Flash Attention 抵消部分损耗 |

## 12. 与 v1.0、v2.0 的关系

```
v1.0 (bge-zh + CLIP-ViT)   纯中文，无 prompt，无时序
       ↓
v1.5 (bge-zh + EVA02)      纯中文，+prompt，+时序检索器     ← 本轮设计
       ↓
v2.0 (e5-small + EVA02)    中英双语，+prompt，+时序检索器    ← 后续
```
