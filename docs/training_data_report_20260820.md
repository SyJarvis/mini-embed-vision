## 3. 已完成的训练实验

### 3.1 实验设置（两轮完全一致，仅数据量不同）

| 配置 | 值 |
|------|-----|
| 硬件 | 3× RTX 6000D（85GB），DDP |
| 全局 batch | 128 × 3 = 384 |
| 优化器 | AdamW，lr 2e-5，weight decay 0.01，linear warmup 5% |
| 精度 | bf16 autocast |
| 训练轮数 | 30 epoch（无 early stop） |
| 模型 | bge-base-zh-v1.5（冻结）+ clip-vit-base-patch32（可训练，87.5M 参数） |
| 损失 | InfoNCE 对比学习，全局负例（AllGatherWithGrad） |

### 3.2 数据量对比结果

| | 16k 数据（v1） | 140k 数据（v2） |
|--|---------------|-----------------|
| 训练集 | 16,114 | 137,273 |
| 验证集 | 339 | 2,804 |
| **最佳 Val R@1** | 56.6% | **62.3%** |
| 最佳 R@5 | 87.9% | 83.9% |
| 最佳 R@10 | 92.3% | 90.2% |
| 峰值出现 epoch | E30 | **E6** |
| E30 时 R@1（过拟合后） | — | 49.7% |
| checkpoint | `checkpoints/best.pth` | `checkpoints_140k/best.pth`（724M） |

> 注：两轮验证集大小不同（339 vs 2804），v2 指标更可信；R@5/R@10 略降属正常——候选池大 8 倍，任务更难。

**结论：数据量 8.6× → R@1 +5.7pp（56.6% → 62.3%），验证「数据量是当前主要瓶颈」。**

### 3.3 训练曲线要点（140k 轮）

```
R@1:  E1 25.1% → E4 62.0% → E6 62.3%(峰值) → E15 55.9% → E30 49.7%
loss: E1 4.70  → E6 1.80   → E30 0.46（持续下降）
```

- **过拟合在 E6 后出现**：train loss 持续降但 Val R@1 单调下滑，E7-E30 白跑
- best checkpoint 机制有效捕获 E6 峰值

### 3.4 真实检索 demo（200 对抽样，checkpoints_140k/best.pth）

| 指标 | 以文搜图 | 以图搜文 |
|------|---------|---------|
| R@1 | 85.0% | 80.5% |
| R@5 | 95.5% | 97.5% |
| median rank | 1 | 1 |

> 候选池仅 200，指标高于训练验证（2804 选 1）属正常。定性观察：命中的 query 涵盖动物/食物/交通工具/人物场景；未命中的 top-5 也多为语义近邻（如「马拉车」检索到「牵狗」），模型学到真实语义对齐而非记忆。

## 4. 问题与下一步

### 4.1 已确认的问题

1. **过拟合来得早**：140k 数据 6 epoch 即过拟合 → 需 early stop / 图像增广 / 更多数据
2. **训练轮数浪费**：best 在 E6，但跑了 30 epoch → 加 early stop（patience=3）
3. **fail-fast 曾中断生成**：服务端连接错误连续 5 次自动停止（已重启，新 key 正常）

### 4.2 下一步计划

| 项 | 目标 | 预期 |
|-----|------|------|
| 继续攒数据 | 40-50 万条（~36 小时后） | 过拟合点后移，R@1 冲 70%+ |
| train.py 改进 | 加 early stop + 图像增广 | 减少浪费 epoch、正则化 |
| 换视觉编码器实验 | EVA02-base-patch14 或 SigLIP-base | 数据量固定后做 ablation，干净归因 |
| 全量数据 | 128 万条（~6.5 天） | 最终版训练 |

### 4.3 风险提示

- 全量生成预计再消耗 **~7 亿 tokens**（VLM API 成本需评估）
- 磁盘剩余 1.4T（81% 已用），全量 parquet 预计 ~110GB，充足
