# 下一代多模态嵌入模型能力分析

> 2026-08-21 | 对比 Qwen3-VL-Embedding 与当前 mini-embed-vision v1.0

---

## 1. Qwen3-VL-Embedding 给了我们什么启示

Qwen3-VL-Embedding 是当前多模态嵌入的 SOTA（MMTEB 68 分，Image 维度 75-80%），它揭示了几个关键趋势：

| 趋势 | Qwen3-VL-Embedding 的做法 | 对下一代模型的含义 |
|------|--------------------------|------------------|
| **LLM is the backbone** | 基于 Qwen3-VL-2B/8B（语言模型本身做视觉理解）| 视觉编码器不再是 ViT，而是 LLM 统一理解 |
| **统一架构胜过分离塔** | 同一个模型编码 text + image + video | CLIP 双编码器架构在换代 |
| **长上下文是刚需** | 32K tokens，支持多图、视频帧拼接 | 当前 128 tokens 完全不够 |
| **指令感知带来 1-5% 提升** | 带 instruct 比不带明显更好 | 没有指令适配的多模态嵌入已经过时 |
| **MRL 是标配** | 64-2048 维度可裁剪 | 用户按需选择维度 |
| **嵌入+重排序一体** | 同时提供 embedding 和 reranker | 纯嵌入不够，需要两阶段 pipeline |

## 2. 我们的 v1.0 和 Qwen3 的差距分析

| 维度 | v1.0 当前 | 差距 | 关键性 |
|------|-----------|------|--------|
| 视觉骨干 | CLIP-ViT-B/32 (patch32, 224×224) | 2011 年的视觉设计，patch 太大，细节损失严重 | ⭐⭐⭐⭐⭐ |
| 文本骨干 | BGE-base-zh (102M, 冻结) | 非 LLM 架构，无法做长上下文，无法做统一表征 | ⭐⭐⭐⭐⭐ |
| 文本-视觉关系 | 分离双塔，各自编码后简单对齐 | 没有跨模态交互，丢失细粒度语义 | ⭐⭐⭐⭐ |
| 上下文长度 | 128 tokens | 无法处理长文本描述、图文混合输入 | ⭐⭐⭐⭐ |
| 嵌入维度 | 768 (固定) | MRL 是标配了 | ⭐⭐⭐ |
| 指令感知 | ❌ | 所有输入用同一方式编码 | ⭐⭐⭐ |
| 重排序 | ❌ | 只有 embedding 没有 reranker | ⭐⭐⭐ |
| 训练数据 | 1 个域 (ImageNet 中文描述, 18万) | 数据多样性不足，域泛化差 | ⭐⭐⭐⭐⭐ |
| 中文优化 | ✅ BGE-base-zh | 中文很好，但英文数据让 BGE 也有能力 | ⭐⭐ |
| 部署效率 | 87M 可训练参数, 0.5GB checkpoint | 轻量但能力上限明显 | ⭐⭐ |

## 3. 我的判断：两条路线选一条

通读 Qwen3-VL-Embedding 的论文和能力表后，我认为我们面临的不是「换什么组件」的问题，而是一次**架构范式跃迁**。当前所有 SOTA 多模态嵌入模型都在从 CLIP 双塔走向 LLM 统一架构。

### 路线 A：「大提升」— 跟随 Qwen3-VL 架构（推荐）

```
输入→ Qwen3-VL LLM (visual encoder + LLM layers) → pooler → [D] 嵌入
                                                         ↓
                                                  CrossModalReranker → 相关性分数
```

**核心变革**：
1. **视觉不再用 ViT**，而是用 LLM 自带的 visual encoder（Qwen3-VL 用的是 SigLIP ViT 但通过 LLM 层统一了特征空间）
2. **文本和图像在同一个 LLM 的 hidden state 空间里**，不再需要两个独立编码器再投影对齐
3. **长上下文天然支持**（32K），可以多图、图文混合、视频帧

**参数规模**：
| 模型 | 总参数 | 可训练 | 预期 MMTEB |
|------|--------|--------|-----------|
| Qwen3-VL-Embedding-2B | 2B | ~300M | 63.9 |
| Qwen3-VL-Embedding-8B | 8B | ~1B | 67.9 |
| **我们如果做 2B 级** | ~2B | ~300M | ~55-60 (取决于数据) |

**代价**：
- 推理显存 ~8-16GB（bf16），**比当前大 16 倍**
- 需要百万级图文对数据，不是当前 18 万量级
- 训练时间从几分钟变成几天

### 路线 B：「稳健升级」— 在当前 CLIP 基础上做上限提升

```
Text → Qwen3-Embedding-0.6B → MLP Proj → [1024]  L2
Image → EVA02-Base-P14      → MLP Proj → [1024]  L2
                                       ↓
                               CrossModalReranker → score
```

这就是 v1.5 计划的方向。相对保守但可行。

**核心变革**：
1. 文本编码器 BGE → Qwen3-Embedding（1024 维，指令感知，长上下文）
2. 视觉编码器 CLIP-B/32 → EVA02-Base-P14（patch14, 更强视觉特征）
3. 投影层从 Linear → MLP
4. 新增 MRL 和 Reranker

**参数规模**：
| 组件 | 参数量 | 可训练 |
|------|--------|--------|
| Qwen3-Embedding-0.6B | 600M | ❌ 冻结 |
| EVA02-Base-P14 | 86M | ✅ 训练 |
| 投影层 + Reranker | ~4M | ✅ |
| **总计** | ~690M | **~90M** |

和 v1.0 完全相同的可训练参数量（87M → 90M），模型容量天花板没变。

## 4. 两条路线对比

| 对比维度 | 路线 A (LLM 统一架构) | 路线 B (CLIP 增强) |
|---------|---------------------|------------------|
| **架构复杂度** | 高，接入 Qwen3-VL | 低，当前架构小改 |
| **训练数据** | 需要百万级图文对 | 18万+ImageNet 即可 |
| **训练时间** | 多卡几天 | 多卡几分钟 |
| **推理成本** | 大 (2B/8B 模型) | 轻量 (87M 可训练) |
| **上下文长度** | 32K (多图/视频) | 256-512 (单图+短文本) |
| **MMTEB 预期** | ~55-60 | ~40-45 (v1.0 ~35 估算) |
| **中文能力** | ✅ 继承 Qwen3-VL 强 | ✅ 中文优化 |
| **与 SOTA 差距** | 合理（差 5-8 分） | 显著（差 20+ 分） |
| **研发周期** | 1-2 月 | 1-2 周 |
| **主要风险** | 数据不足，训练不稳定 | 架构上限低 |

## 5. 我的建议：分两步走

### 第一步（1-2 周）：走路线 B，把 v1.5 做出来

- 换 Qwen3-Embedding-0.6B + EVA02-Base-P14
- 1024 维，支持 MRL
- 加指令感知
- 加 Reranker Head
- **用现有 ImageNet-zh 数据先训一轮**，确认架构能收敛
- 对比 v1.0 的 R@1 提升（预期 ~5-8pp）

这一步投入小、风险可控、能快速确认改进方向有效。

### 第二步（长期）：用现在的 benchmark 验证结果来争取资源

先用路线 B 产出 **MMTEB benchmark 分数**（分类+检索+聚类），证明模型达到了什么水平。然后你带着 benchmark 结果，可以更有说服力地决定：

- 「Qwen3-VL-Embedding-2B 能做到 63.9，我们差了 X 分，主要是因为：① 架构不是 LLM 统一；② 数据量不够」
- 基于具体差距决定下一步（收集数据 vs 换架构 vs 继续调 v1.5）

## 6. 如果我们选路线 A，需要的能力清单

如果决定「一步到位」跳到 Qwen3-VL-Embedding 级别的架构：

### 必须的能力

| 能力 | 具体含义 | 实现方式 |
|------|---------|---------|
| **LLM 统一编码** | text 和 image 进入同一个 LLM | 基于 Qwen3-VL-2B 改 embedding head |
| **长上下文** | 至少 8K 有效 | flash_attention_2 + left padding |
| **多图/图文混合** | 单条样本含多图 + 文本 | 利用 Qwen3-VL 的 chat template |
| **指令感知** | 按任务给不同 instruct | `Instruct: {task}\nQuery: {input}` |
| **MRL** | 64-2048 维度裁剪 | 训练时多维度对比损失 |
| **重排序** | 轻量 cross-encoder | 参考 Qwen3-VL-Reranker 或直接复用 |
| **量化** | int8/int4 输出 | 嵌入量化训练或 PTQ |
| **多语言** | 中英为主，覆盖 30+ | Qwen3-VL 已支持 |

### 需要的训练数据

| 数据源 | 规模 | 优先级 |
|--------|------|--------|
| 高质量图文对（COCO-CN/Flickr30K-CN） | 10 万级 | ⭐⭐⭐ |
| 图文对（Wukong/LAION-CN filtered） | 百万级 | ⭐⭐⭐ |
| 合成数据（用 VLM 生成描述） | 百万级 | ⭐⭐ |
| 难负例 (hard negatives) | 10 万级 | ⭐⭐ |
| 纯文本 + 文本检索数据 | 百万级 | ⭐⭐ |
